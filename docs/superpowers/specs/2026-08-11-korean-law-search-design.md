# 건축·도시계획 법령 통합검색기 설계

## 1. 목표

국가법령정보 공동활용 API를 이용하여 현행 법령, 행정규칙, 선택한 지방자치단체의 자치법규를 한 검색창에서 찾는 Windows 로컬 웹앱을 만든다. 사용자는 일반 키워드 또는 `@지역 키워드` 형식으로 검색하며, 결과에서 일치 문맥과 시행일을 확인하고 국가법령정보센터 공식 원문으로 이동할 수 있다.

첫 번째 버전은 검색 정확성과 출처 추적에 집중한다. AI 요약, 법률적 결론 생성, 사용자 로그인, 외부 공개는 포함하지 않는다.

## 2. 사용자와 실행 환경

- Windows PC 한 대에서 한 명이 사용한다.
- 사용 빈도는 매일이 아니라 특정 기간의 집중 검색이다.
- `run.bat`를 실행하면 로컬 Streamlit 서버가 시작되고 기본 브라우저에서 화면이 열린다.
- 국가법령정보 공동활용 API 인증값은 기존 외부 인증정보 파일에서 런타임에 읽는다.
- 인증값 자체는 소스코드, 로컬 설정, SQLite, 로그, 테스트 출력에 저장하지 않는다.

## 3. 검색 문법

### 3.1 기본 검색

`주차 대수`처럼 지역 지시자 없이 입력하면 자치법규를 검색하지 않고 다음 자료를 검색한다.

1. 현행 법률
2. 대통령령·시행령
3. 총리령·부령·시행규칙
4. 행정규칙·고시
5. 그 밖의 상위 규정

### 3.2 지역 우선 검색

`@평택 주차 대수` 또는 `주차 대수 @평택`처럼 입력하면 지역 토큰과 실제 키워드를 분리한다. `@평택`은 자동완성 선택을 통해 `경기도 평택시` 및 공식 기관코드로 확정한다.

중복 지역명은 임의로 선택하지 않는다. 예를 들어 `@중구`는 서울특별시 중구, 부산광역시 중구 등 후보를 표시하고 사용자가 하나를 선택해야 검색을 실행한다. 사용자는 `@경기/평택`처럼 광역·기초 지자체를 함께 입력해 즉시 확정할 수도 있다.

지역이 확정된 검색의 결과 그룹 순서는 다음과 같다.

1. 선택한 시·군·구의 자치법규
2. 해당 상위 광역지자체의 자치법규
3. 법률
4. 대통령령·시행령
5. 총리령·부령·시행규칙
6. 행정규칙·고시
7. 그 밖의 상위 규정

### 3.3 검색어 일치 기준

- API 본문검색 `search=2`를 기본으로 사용한다.
- 정확 문구 일치를 가장 높은 순위로 둔다.
- 띄어쓰기만 다른 일치를 다음 순위로 둔다. 예: `주차 대수`와 `주차대수`.
- 모든 검색 단어가 같은 결과에 포함된 경우를 보조 결과로 둔다.
- AI가 유사 개념이나 동의어를 임의로 생성하지 않는다.

## 4. 공식 법령용어 추천

검색창 아래에 법제처의 법령용어 및 일상용어-법령용어 연계 API에서 받은 후보만 표시한다. 후보가 없으면 추천을 만들지 않는다. 추천어를 클릭한 경우에만 해당 용어로 다시 검색한다.

추천 기능은 검색 결과와 분리하여 실패할 수 있다. 용어 API가 실패해도 법령·자치법규 검색 결과는 표시한다.

## 5. 아키텍처

```text
Streamlit UI
    ↓
Query Parser ── Region Registry
    ↓
Search Service
    ├─ Law API Adapter
    ├─ Administrative Rule API Adapter
    ├─ Ordinance API Adapter
    └─ Legal Term API Adapter
    ↓
Normalizer and Ranker
    ↓
SQLite Cache
```

### 5.1 Streamlit UI

검색창, 지역 자동완성, 추천 법령용어, 결과 그룹, 상세 본문, 공식 원문 링크, 새로고침 기능을 제공한다. UI는 검색 요청을 구성하고 결과를 표현하며 API 형식이나 정렬 규칙을 직접 알지 않는다.

### 5.2 Query Parser

원문 입력에서 `@` 지역 토큰을 최대 하나 추출하고 나머지를 검색어로 정규화한다. 지역이 없으면 자치법규 검색을 요청하지 않는다. 빈 검색어와 여러 개의 지역 토큰은 명시적인 검증 오류로 반환한다.

### 5.3 Region Registry

법제처가 제공하는 지자체 기관코드를 사용하여 지역 이름, 광역코드 `org`, 기초코드 `sborg`, 상위 광역지자체 관계를 관리한다. 표시용 별칭은 검색 편의를 위해 허용하지만 API 요청에는 항상 공식 코드를 사용한다.

### 5.4 API Adapters

각 API 어댑터는 요청 생성, 제한시간, 응답 파싱, 오류 변환만 담당한다. 인증값을 URL이 포함된 로그나 예외 메시지에 노출하지 않는다. 모든 통신은 HTTPS를 우선 사용하고 리디렉션을 제한적으로 허용한다.

### 5.5 Search Service

지역 없는 검색에서는 현행 법령, 행정규칙, 법령용어 API를 병렬 호출한다. 지역 검색에서는 기초지자체 자치법규와 상위 광역지자체 자치법규를 추가한다. 한 API의 실패가 다른 API 결과를 폐기하지 않도록 부분 성공을 지원한다.

### 5.6 Normalizer and Ranker

서로 다른 API 응답을 공통 검색 결과 모델로 변환한다. 공통 모델은 자료 ID, 제목, 자료 종류, 소관기관, 지자체, 공포일, 시행일, 현행 여부, 일치 문맥, 공식 링크, 조회 시각을 가진다. 자료 ID와 자료 종류를 기준으로 중복을 제거한 뒤 승인된 그룹 순서와 일치 기준으로 정렬한다.

## 6. 데이터 흐름

1. 사용자가 검색어를 입력한다.
2. Query Parser가 지역 토큰과 키워드를 분리한다.
3. Region Registry가 지역을 하나의 공식 기관코드 조합으로 확정하거나 후보를 반환한다.
4. Search Service가 캐시 키를 계산한다.
5. 강제 새로고침이 아니며 24시간 이내 캐시가 있으면 캐시 결과를 사용한다.
6. 캐시가 없거나 만료됐으면 필요한 API를 비동기로 병렬 호출한다.
7. 응답을 공통 모델로 변환하고 중복 제거·정렬한다.
8. 결과와 조회 시각을 SQLite에 저장한다.
9. UI가 그룹별 결과와 데이터 상태를 표시한다.
10. 사용자가 본문을 펼칠 때만 해당 자료의 본문 API를 호출하고 별도 캐시에 저장한다.

## 7. 캐시 정책

- 검색 목록과 상세 본문 캐시를 분리한다.
- 기본 유효기간은 24시간이다.
- `새로고침`은 유효한 캐시도 무시하고 공식 API를 다시 호출한다.
- API 장애 시 만료된 캐시가 있으면 마지막 조회 시각과 경고를 함께 표시한다.
- 30일 이상 접근하지 않은 캐시는 정리한다.
- 캐시 키에는 정규화 검색어, 지역코드, API 대상, 검색범위, 페이지가 포함된다.
- 인증값과 인증값이 포함된 전체 요청 URL은 저장하지 않는다.
- SQLite 파일은 Git 추적에서 제외한다.

## 8. 화면 설계

상단에는 제목, 검색창, 검색 버튼, 사용 예시를 배치한다. 지역을 선택하면 `경기도 평택시` 칩을 표시하고 칩의 제거 버튼으로 지역 조건을 해제할 수 있다.

검색 결과는 승인된 우선순위에 따라 그룹으로 표시한다. 각 결과 카드에는 다음 정보를 표시한다.

- 법령·자치법규명
- 법규 종류
- 소관기관 또는 지자체
- 공포일 및 시행일
- 현행 여부
- 검색어가 발견된 조문 또는 문맥
- API 조회 시각 및 캐시 상태
- 본문 펼치기 버튼
- 국가법령정보센터 공식 원문 링크

각 그룹은 접거나 펼칠 수 있다. API 한 페이지의 최대 결과 수는 100건으로 제한하고, 추가 결과는 `더 보기`로 다음 페이지를 요청한다.

## 9. 오류 처리

- 인증정보 파일을 읽을 수 없으면 경로 확인 방법만 표시하고 인증값은 표시하지 않는다.
- 중복 지역명은 후보 선택 전까지 검색을 실행하지 않는다.
- 존재하지 않는 지역명은 가까운 지역명 후보만 표시한다.
- 일부 API가 실패하면 성공 결과와 실패한 자료 그룹의 재시도 버튼을 함께 표시한다.
- 각 API 요청은 10초 후 중단하고 부분 결과를 반환한다.
- 전체 API가 실패하면 만료 캐시를 경고와 함께 사용하고, 캐시도 없으면 재시도 화면을 표시한다.
- 예상하지 못한 응답 형식은 민감정보 없는 구조화 오류로 기록한다.
- 결과가 없으면 공식 법령용어 후보와 검색어 수정 안내를 표시한다.

## 10. 보안 및 법적 표시

- 앱은 `127.0.0.1`에만 바인딩한다.
- 외부 인증정보 파일의 경로는 Git에서 제외한 로컬 설정 또는 환경변수로 전달한다.
- 인증값은 메모리에서 API 호출에만 사용하며 마스킹되지 않은 형태로 출력하지 않는다.
- 모든 결과에 `출처: 국가법령정보센터`를 표시한다.
- 자치법규·행정규칙 결과에는 `참고자료이며 최종 확인은 공식 원문 및 소관기관 기준`이라는 경고를 표시한다.
- AI 요약이나 법률적 판단을 제공하지 않는다.

## 11. 테스트 전략

### 11.1 단위 테스트

- 지역 없는 검색어 파싱
- 앞 또는 뒤에 있는 `@평택` 파싱
- `@중구` 중복 후보 반환
- 유효하지 않은 지역과 여러 지역 토큰 거부
- 지역 유무에 따른 API 호출 대상 선택
- 그룹 및 일치도 정렬
- JSON의 단일 객체와 배열 응답 정규화
- 캐시 적중, 만료, 강제 새로고침, 장애 시 만료 캐시 사용
- 인증값이 캐시와 로그에 저장되지 않음

### 11.2 통합 테스트

실제 인증정보를 사용할 수 있을 때 별도로 실행하는 테스트로 현행 법령, 행정규칙, 평택시·경기도 자치법규, 법령용어 API의 응답 형태와 공식 링크를 검증한다. 통합 테스트는 검색 건수나 특정 법령 존재 여부처럼 시점에 따라 바뀌는 값을 고정하지 않는다.

### 11.3 수동 인수 테스트

1. `주차 대수` 검색에 상위법 그룹만 표시된다.
2. `@평택 주차 대수` 검색에 평택시와 경기도 자치법규가 상위법보다 먼저 표시된다.
3. 일치 문맥, 시행일, 현행 여부, 공식 링크를 확인할 수 있다.
4. 동일 검색 반복 시 캐시 사용 상태가 표시된다.
5. 새로고침 시 공식 API를 다시 호출한다.
6. 앱 재시작 후에도 캐시가 유지된다.
7. `run.bat`로 앱이 실행된다.
8. 프로젝트·SQLite·로그에서 API 인증값이 발견되지 않는다.

## 12. MVP 제외 범위

- AI 요약 및 질문답변
- 판례, 헌재결정례, 법령해석례, 행정심판례 검색
- 외부 사용자 로그인과 권한관리
- 인터넷 공개와 서버 배포
- 법령 전체의 로컬 복제
- 법률적 결론 또는 인허가 가능 여부 자동 판정
